# Контракт ML и Backend: версия 2.0

V1 сохранён: scoring_request.schema.json — 20 полей, scoring_result.schema.json —
прежние четыре поля. scoring_requests.json — три интеграционных примера без меток.
Отсутствующий docs/00_common.md для запуска не требуется.

score(req: ScoringRequest) -> ScoringResult; типы из ml.dto.
V2-вход: schema_version="2.0", application_id, request с вложенным запросом v1.
JSON Schema v2 использует локально зарегистрированный URN канонической схемы v1.
Голый v1 поддерживается с идентификатором legacy-<hash>, Pydantic v2 — через model_dump.

Внутренний ответ v2: application_id, schema_version, pd, risk_band, model_version,
reasons, technical_status="OK", request_hash, details. Ошибки — типизированные исключения.
request_hash связывает PD с конкретными условиями. to_v1() сохраняет совместимость.

Деньги и сроки — целые, тренд — доля, ОКВЭД/регион — строки, флаги — bool.
Лишние/отсутствующие поля, float/bool вместо целого, NaN и Infinity запрещены.
Нельзя иметь текущий долг/платежи при active_loans=0. Срок обслуживания не дольше
возраста бизнеса. Технический предел чисел 10^15. Дата и метка не являются входами.
Неизвестный ОКВЭД поддерживается; неизвестный продукт отклоняется.

A [0,.05), B [.05,.10), C [.10,.20), D [.20,1]. Изменения границ требуют согласования.
Скоринг получает заявки после стоп-факторов и дополнительно отклоняет неактивность,
defaults>0 или просрочку>90 как OutOfDomainError. Не устанавливает банковский статус.

CreditDecision и LoanOffer описаны отдельными схемами. Цель и подтверждение объекта
инвестиций передаются отдельно в optimize(). Только ELIGIBLE поступает в оптимизатор;
каждый кандидат снова получает PD и проверяется политикой.

public_result.schema.json содержит только application_id, фиксированный код и
публичные условия. Дополнительные поля запрещены, включая вложенные.
Использовать OptimizationResult.public(), не отдавать внутренний ScoringResult клиенту.
Вклады не превращаются автоматически в юридические основания или уведомления.
Аудит отказов, авторизация, история статусов и уведомления относятся к Backend.

Загрузить ModelScorer один раз. Версии, хэши, preprocessing и порядок фич проверяются.
Скрытого fallback нет. Примеры: reports/backend_examples.json, reports/offer_examples.json.
