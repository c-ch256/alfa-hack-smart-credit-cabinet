# ML: локальный скорер Craftors

Контракт backend v1 без изменений находится в `ml/contracts/`.
Текущее состояние: датасет сгенерирован, пять тестов генератора проходят.
Код обучения, инференса и контрактных тестов подготовлен, но пока не выполнен:
установка CatBoost в рабочей среде зависает на загрузке wheel. Обученных
артефактов и измеренных метрик модели пока нет. Не считать код проверенным
до выполнения команд ниже.
Команды выполнять из корня репозитория, Python 3.12. После установки
зависимостей генерация, обучение и инференс работают без сети.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ml/requirements.txt
.\.venv\Scripts\python.exe ml/generate_data.py --n_samples 15000 --seed 42 --output data/synthetic_data.csv
.\.venv\Scripts\python.exe -m ml.train
.\.venv\Scripts\python.exe -m unittest discover -s ml/tests -v
```

Рядом с CSV появляется `synthetic_data.metadata.json` с seed, версией генератора,
долей дефолтов и допущениями. Одинаковые аргументы и версии библиотек дают
одинаковые данные. По умолчанию создаётся 15 тысяч строк. CSV содержит ровно
20 входных полей (плоское представление вложенного запроса), дату и метку.
При чтении CSV обязательно задавать `dtype={'okved': str}`.

Каждая строка — синтетический выданный кредит. `default_12m = 1` означает
просрочку 90+ дней в течение 12 месяцев после выдачи, а не отказ банка.
Сначала создаются признаки, затем латентная вероятность, затем случайный
Bernoulli-исход. Средняя вероятность настраивается на 6.5%; фактическая доля
дефолтов колеблется. Вероятность и латентный риск в CSV не сохраняются.

Даты выдач: 24.10.2023–23.10.2025. Дата наблюдения фиксирована: 23.10.2026,
поэтому для всех строк завершён год наблюдений. Последние 6 месяцев выдач —
независимый тест. Оставшиеся данные делятся стратифицированно: 70% обучение,
15% early stopping, 15% Platt-калибровка. Дата и метка исключены из признаков.

Доступны `working_capital` (300 тыс.–30 млн, 3–36 мес.) и `investment`
(1–100 млн, 12–84 мес.). Для выданных инвесткредитов от 5 млн залог заполнен.
Нет активных кредитов — нет текущего долга и платежей. Срок отношений с банком
не превышает возраст бизнеса. Денежные суммы в рублях, тренд в долях единицы.
`tax_debt` и `mass_address` — булевы флаги; `okved` — строковый код,
`region` — название региона; `status` — статус ФНС на дату заявки.

`features.py` одинаково вычисляет признаки при обучении и инференсе.
Ставка не предполагается: `principal_monthly = amount / term_months` —
только основной долг в расчёте на месяц. `principal_coverage` — денежный поток,
делённый на текущие платежи плюс эту величину. Это не итоговый платёж и не DSCR.
Финальный DSCR и решение рассчитывает backend. Обязательные пропуски/NaN
отклоняются, знаменатели ограничиваются единицей, отношения — диапазоном
[-100, 100]; неизвестные строковые категории поддерживаются CatBoost.

```python
from ml.inference import ModelScorer

scorer = ModelScorer('ml/artifacts')  # создать один раз при старте backend
result = scorer.score(request)  # dict или Pydantic v2 ScoringRequest
# Если backend требует свой класс: ScoringResult.model_validate(result)
results = scorer.score_many([request])
```

Возвращается JSON-совместимый dict `{pd, risk_band, model_version, reasons}`.
Границы групп: A < 5%, B < 10%, C < 20%, D >= 20%.
Backend подключает адаптер при `SCORER=model`; путь берётся из `MODEL_DIR`.
Python-классы backend в архив не включены: наследование от его `Scorer`
и преобразование dict в его `ScoringResult` остаются на стороне интеграции.
Ошибки загрузки не скрываются: backend должен залогировать их и явно выбрать
MockScorer, если такой fallback предусмотрен. Скорер не принимает решений.

`reasons` — четыре максимальных по модулю реальных SHAP-вклада. Вклад выражен
в исходных log-odds CatBoost до Platt-калибровки, не в процентах PD.
Файлы модели: `model.cbm`, `calibration.joblib`, `metadata.json`,
`feature_schema.json`. Отчёт: `ml/reports/metrics.json`, ROC и калибровочная
кривая. Метрики показываются до и после калибровки; калибровка не обязана
улучшать качество на конечном тесте.

Ограничения: выборка уже выданных кредитов после стоп-факторов MVP, без
исторических дефолтов и просрочек свыше 90 дней. Отказанных заявок нет;
reject inference не реализован. Влияния признаков и распределения заданы
вручную, временной дрейф не моделируется. Регион и ОПФ напрямую не влияют
на метку. Метрики на синтетике не подтверждают качество на реальных данных.
Нельзя менять генератор ради нужного AUC или конкретного демо-исхода.
