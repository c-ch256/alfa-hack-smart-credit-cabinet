# Сценарий демо, 6 минут 30 секунд

**Главная мысль для жюри:** одна заявка проходит от «нужны деньги» до «кредит выдан» без повторного ввода данных: клиент на каждом шаге видит статус и следующий шаг, а аналитик — полную картину решения.

Цифры — при `KEY_RATE=14`, маржах +4 / +3 и скорере `mock` ([06_demo_profiles.md](06_demo_profiles.md)). В режиме `model` у client2 ставка встречного 18%, платёж 126 533 ₽.

## Подготовка (за 10 минут)

1. **Чистая база** с демо-данными: `docker compose down -v`, затем `docker compose up --build` и открыть **http://localhost:8080** (интерфейс). `.env` заполнить заранее по README.
2. **Два окна браузера** рядом, масштаб 100%, ширина от 1280: слева клиент, справа staff1.
3. **Не обновлять страницу (F5)** — сессия хранится в памяти вкладки, после обновления придётся входить снова. Переходить только кнопками и меню.
4. **Резерв:** открыт Swagger `http://127.0.0.1:8000/docs`, в терминале готов `python docs/product/smoke_scenarios.py http://127.0.0.1:8000 <пароль>` — все исходы за несколько секунд.
5. **Роли:** ведущий говорит, оператор кликает.

## Если что-то пошло не так

| Проблема | Что делаем |
|---|---|
| Выбросило на вход | Войти снова — данные на месте. Не нажимать F5 |
| Фронтенд не открылся | Показываем тот же путь в Swagger: вход → создание → подача → решение |
| Цифры не совпали со сценарием | Не спорим с экраном: проверить `KEY_RATE` и режим `SCORER`; объясняем по карточке сотрудника |
| Время на исходе | Пропускаем client4 (5:15–5:40) |
| Нет интернета | Ничего не меняется: всё работает локально |

## Вопросы жюри — короткие ответы

| Вопрос | Ответ |
|---|---|
| «Где тут ИИ?» | Модель (логистическая регрессия на синтетике) оценивает вероятность дефолта и объясняет факторы. Решение принимает прозрачная политика — так работает банковская практика, и продукт работает даже без модели |
| «Ставки рыночные?» | Ставка = ключевая ЦБ 14% + маржа продукта + надбавка за риск: оборотный 18–23%, инвестиционный 17–22%. Это демонстрационные условия; рыночные онлайн-кредиты МСБ — от 25,5% (ВТБ), маржу можно поднять настройкой |
| «Почему клиент не видит причину отказа?» | Раскрытие причин позволяет подгонять заявку под правила. Клиент видит статус и следующий шаг, получает встречное предложение вместо отказа; полная картина — у аналитика (П12) |
| «Почему клиент не видит PD?» | Это внутренняя оценка банка; клиенту нужен понятный ответ и следующий шаг |
| «Что с большими суммами?» | Свыше 30 млн ₽ — всегда к специалисту |
| «Как масштабировать?» | Конвейер в MVP синхронный; очередь не меняет статусы и правила. Моки заменяются клиентами реальных шлюзов, скоринг — моделью на реальных данных через тот же контракт |
| «Почему AUC такой высокий?» | Синтетика сгенерирована простой формулой, модель её почти «угадывает». На реальных данных метрики будут ниже — это записано в MODEL_CARD |
